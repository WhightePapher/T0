# t0办公 · 视觉设计说明

## 一、视觉关键词

**克制、专业、纸感、可控。** t0办公要回答的问题是「AI 生成的汇报，我还能不能改」，所以整套视觉刻意避开常见的科技渐变与发光：底色用偏暖的纸白，网格线细到几乎看不见，强调色只保留一种沉绿。界面里没有装饰性插画，层级靠字号、留白和一条 1px 细线建立，让用户的注意力始终落在「结构」和「当前模块」上。

## 三、字体规范

- 全部字体随应用打包，**不联网取字体**：`assets/fonts/` 下是 `tool/prepare_fonts.py` 从系统 Noto Sans SC / Noto Serif SC 变量字体生成的子集 + 静态字重（400/600/700），Cascadia Mono 只保留拉丁子集。
- 打包后的家族名：`T0Sans`（正文 / UI）、`T0Serif`（标题 / 封面）、`T0Mono`（数字 / 版本）。三者在 `fontFamilyFallback` 里互相兜底，永远不会去 Google CDN 取 Noto。
- 为什么必须打包：Flutter web（CanvasKit）不认系统字体名，`MiSans`、`Source Han Serif SC` 在本机不存在时只能靠引擎内置字体，结果就是「巨号标题变黑体 + 少数字缺字形变 ☒」。`tool/font_coverage.py` 会把 `lib/` 里所有字符串字面量的非 ASCII 字符逐个对照 cmap，输出 `missing: 0` 才算过。
- 字号阶梯：display 64/72（700，行高 1.05，字距 -1.5）、h1 34/42、h2 22/30、body 15/26、meta 12/18、eyebrow 11/16（字距 3，前置 34px 细线）。窄屏按断点整体缩一档，正文最小不低于 13px，保证手机端可读。

## 四、按钮与图标规范

主按钮是绿色胶囊（圆角 999），三态：默认 #147A62、悬停转 #0E5F4D 并浮起 0 18px 60px 阴影、按下再压一档；禁用态退回 line 底、muted 字。次要按钮为 1px 描边胶囊，幽灵按钮只有文字和悬停下划线。卡片统一 18 圆角 + 1px line 边框，只有真正的浮起层（悬停卡片、弹窗、Toast）才用统一阴影。图标全部走 Material 线性图标（24 网格、1.5px 描边），品牌方块 `t0` 用代码绘制，不引入任何位图。

## 五、布局与响应式

≥1100px 为桌面：内容最大宽 1360、左右留白 96，模块工作区三栏 280 / 自适应 / 380；700–1099 为窄桌面：工作台单列、说明卡下移，工作区右栏改成可收起的抽屉；<700 为手机：全部单列、导航收成图标 + 菜单、画布横向滚动、按钮全宽。六个界面在 500px 宽度下均无溢出（`test/layout_smoke_test.dart` 覆盖）。

## 六、AI 参与的环节

1. **风格方案**：用 AI 生成三套「暖纸 + 沉绿」方向参考，人工筛掉偏插画与偏科技的两套，保留最克制的一版，再按设计令牌落地。
2. **产品内的 AI**：材料输入页的解析预览、大纲页的结构建议（可采纳 / 忽略、采纳才写进大纲）、模块工作区的 AI 修改面板（chips 只填入输入框、不自动提交；应用后只改当前模块，可撤销回版本 1）。这些是实验五要求的「AI 生成 + 人工筛选与修改」在交互层的体现。
3. **视觉资产**：图标与品牌方块由代码与图标库生成，人工统一线宽与圆角；文案由 AI 起草后按「不编造结论」的原则人工改写过一遍。

## 九、v4 双主题（白天 / 黑夜）

- **白天**保持「暖纸 + 沉绿」不变，色值一个未改（新截图与 v3 的面积最大 8 种颜色逐一相同）。
- **黑夜**以 `#42374B`（H≈282° S≈15% L≈25%）为基准色，沿同一色相做明度阶梯：`bg0 #241D2A` → `bg #2E2536` → `surface #3A2F44` → `surface2 #463A52`，文字 `ink #F3EEF7` / `ink2 #C6BACE` / `muted #B8ADC4`（muted 在 v6 卡里从 `#9C8FA9` 提亮，卡面上 5.88:1）。
- **黑夜是冷紫灰系，不是暖纸的深色版**：暖黄的纸感只在白天成立，深色下沿用暖色会发脏、并让品牌绿失去对比。这条是既定设计口径（基准色由任务书指定），不随截图反馈改色值；「暖纸」调仅适用于白天。
- 角色分工不变：绿色（`accent #4FB08B`）承担主操作 / 已确认，紫色（`lilac #B79BD6`）承担选中 / 强调 / 装饰。状态色 `ok #6FBF9B` / `warn #E0A268` / `danger #F09189`（r4 从 `#E07A72` 提亮一档：11px「模拟解析失败」压卡面 `#3A2F44` 原来 4.31:1，现在 5.46:1；浅色 `#A63F36` 未动）。
- 切换：420ms、`easeInOutCubic`。**面**（底色 / 卡片 / 描边 / 阴影 / soft 底）连续插值；**文字与图标**不做交叉淡入，在中点直接切换，并在过渡途中向同侧 `ink` 收拢 95%——否则底色正在中间灰时任何色相都会糊进去（实测 `#147A62` on `#777077` = 1.09:1）。代价是过渡瞬间强调色短暂去饱和，换来任意一帧文字对比度 ≥3:1（`docs/screenshots_v4/README.md` 有 105/210/315ms 的逐块实测）。
- **画布 / 幻灯片用固定 deck 配色**（与白天完全一致，不随主题变深）：画布是「导出物预览」，深色主题不应影响导出内容。
  **深色主题不影响 deck 纸面**：切到黑夜后舞台底色仍是 `#EBE6DB`、纸卡仍是 `#FFFDF8`、封面仍是 `#17211F`，
  与浅色逐像素相同（`docs/screenshots_v11/05_workspace_dark.png` 里量到的纸卡底边 y=797、页脚线 y=831 与浅色那两张一致）——
  只有应用外壳（顶栏 / 侧栏 / AI 面板 / 页脚）跟着主题变。这是既定口径，不是漏改。
- 对比度：黑夜主题所有文字/底配对 ≥4.5:1、标题 ≥7:1（`test/widget_test.dart` 里 21 组配对逐条断言）。白天仍有一处历史值没过 4.5：「已确认」胶囊 `accent #147A62` on `accentSoft #DFF0E9` = 4.46（「待补充」胶囊在 r2 已提到 4.89，本轮未动这两处）。

## 过渡中点为什么字会变纯黑 / 纯白

420ms 的主题渐变里，页面底色会经过一段中灰（`#A0A0A0` 一带）。任何主题色压在中灰上都不够读
（实测最差 1.09:1），所以 `T0Palette.lerp()` 在中灰段把**前景色**（文字 / 图标 / 描边）收到亮度极值：
底色偏亮时用纯黑、压暗之后用纯白，每一帧取黑白里对比度更高的那个（理论上限 4.58:1 起）。
这只作用于"前景"，**填充**（主按钮底色、进度环、进度条）走 `accentFill` / `accentStrongFill`
的连续插值，永远是绿系、不会黑一下白一下。极值兜底是刻意的可读性保证，不是闪烁 bug，
过渡时长也保持 420ms 不变。
