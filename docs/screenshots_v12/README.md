### #2 三条分隔线

| | 三条线 y | 线间距 | 三行标题墨迹顶边 y | 行距 | **线 → 标题** |
|---|---|---|---|---|---|
| v11 基线 | 623 / 677 / 722 | 54 / 45 | 639 / 684 / 729 | 45 / 45 | **16 / 7 / 7** |
| 现在 | 633 / 678 / 723 | 45 / 45 | 639 / 684 / 729 | 45 / 45 | **6 / 6 / 6** |

- 要求「三条一致、7±1」→ 实测 6 / 6 / 6，极差 **0**，落在区间内。
- 条目行距仍是 45 / 45（没被这次改动带偏），纸卡底边 y=797 → 页脚上边框 y=831 **34px**（r7 基线复量，要求 ≥20）。
- 线为什么不是纯 `#D9D4C9`：1px 的 deckLine 在 71% 缩放下只覆盖半行像素，落屏是线和纸色各半（实测 `#E6E2D9`），所以量尺判据用「离纸色 8–60 的像素占满一行」而不是等色。

## 3. 证据要求：`press_01_light.png` 里没有 toast

上一轮这张图「hover 高亮 + 已撤销提示条」同框，本轮按任务书第一条路走（重拍、等 toast 消失），并且加了像素证明：

- 点「撤销」后 **0.35s** 截一张（不落盘）：toast 取样带 `(590,812)-(860,868)` 里深色像素 **7923** 个 —— 正对照，说明这条检测认得出 toast。
- toast 是 2400ms 后移除的；从点击起等满 **3.2s** 再悬停截图：同一取样带深色像素 **0** 个。
- 同一张图里「按住看修改前」量得到悬浮胶囊 `x=821..931`（宽 110px）→ hover 确实生效。
- 图里右侧面板写着「当前为版本 1，应用修改后会生成版本 2。」，顶部版标 `v1`，与「已撤销」后的状态一致。

取样带刻意避开页脚左侧文案（x≤570）和右侧两个按钮（x≥870），否则页脚文字会污染判据。

  --project <本 worktree> --shots docs/screenshots_v12
