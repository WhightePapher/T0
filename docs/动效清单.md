# 动效清单（Lab5 · t0 办公）

> 本轮只加动效：布局、配色、文案、字号、断点、`theme/palette.dart` 的 420ms 主题渐变与过渡中点前景兜底**一律未动**。
> 行号按本分支最后一次提交（`feat/motion`）；`context.anim(...)` 指 `palette.dart:605` 那个「主题渐变中归零」的出口。

## 0. 运动令牌 `lib/theme/motion.dart`

| 类别 | 令牌 | 值 |
|---|---|---|
| 时长 | `T0Motion.instant` | 90ms（按压、微反馈） |
| 时长 | `T0Motion.fast` | 150ms（内容替换、状态切换） |
| 时长 | `T0Motion.base` | 240ms（页面转场、卡片入场） |
| 时长 | `T0Motion.slow` | 380ms（整屏级，预留） |
| 曲线 | `T0Motion.enter` | `Cubic(0.16, 1, 0.30, 1)` |
| 曲线 | `T0Motion.exit` | `Curves.easeInCubic` |
| 曲线 | `T0Motion.standard` | `Curves.easeOutCubic` |

分组专用时长（都是四档的取整或组规定值）：`pageIn 240` / `pageOut 180` / `title 200` / `stepPulse 320` / `cardIn 320` /
`ring 600` / `moduleCardIn 280` / `failCard 220` / `dialogIn 220` / `dialogOut 160` / `hint 120` / `checkStroke 300` /
`breathe 1600` / `shimmer 1200` / `toast 200` / `toastHold 2400` / `rowResize 240` / `highlightFade 3000`；
错峰 `staggerCard 45` / `staggerModule 40` / `staggerOutline 30` / `staggerCheck 60` / `staggerComparePane 40`。

统一出口：**`T0Motion.dur(context, 时长)` → `context.anim(...)`**。原来散在各处的 140/150/160/200ms
共 30 处 `context.anim(...)` 调用点全部改成 `T0Motion.dur(...)`（43 处引用），
新写的动效一律只从这里取时长。剩下的裸 `Duration(milliseconds: …)` 只有四类，都不是动效：
`--perf` 脚本的等待、工作区里 1.1s 的「假处理中」、Tooltip 的 `waitDuration`、
以及**动不得的** `AnimatedTheme` 420ms（`main.dart:213`）。

三条全局机制：

1. **主题过渡让路**：`palette.dart:605` 的 `context.anim()` 在 `pal.transitioning` 时返回 0（原有逻辑，未改）。
2. **减弱动效**：同一个 `context.anim()` 里加了 `MediaQuery.maybeDisableAnimationsOf(this) → Duration.zero`
   （红线条 6 建议的「改一处、全局生效」）。所有隐式动画、`T0Enter`、进度环、勾选描线、弹层、Toast 一起归零；
   循环类（呼吸点、骨架 shimmer）走 `T0Loops.enabled` + 时长为 0 两条闸，直接停在落位值。
3. **抓帧放慢**：`T0Motion.captureScale`（`--motion=` / `?motion=`）只影响截图进程里的时长，令牌值与曲线不改。

## 2. 性能自证

原则：动画都包在**最内层**那一两个 `AnimatedBuilder` / 隐式动画 / `TweenAnimationBuilder` 里，
`child` 一律通过 `AnimatedBuilder.child` 传下去，动画期间子树不 `build`。
`test/motion_test.dart` 的「入场动画期间子树不重建」用探针实测了这条：动画中间连续 4 帧，
探针 `build` 次数 0，外层 `Transform` 的位移确实在 0→8 之间 —— 说明动画在跑、子树没重建。

| 动效 | 每帧重建的 widget | 说明 |
|---|---|---|
| G1 页面转场 | 1 个 `_FadeUpTransition` → 每帧 1 个 `Opacity` + 1 个 `Transform` | 页面本体在 `child` 里，不重建 |
| G2a 步骤线 | 1 个 `TweenAnimationBuilder` → 1 个 `CustomPaint` | 每帧两笔 `drawRect` |
| G2b 步骤圆点 | 1 个 `AnimatedBuilder` → 1 个 `Stack` + 1 个 `CustomPaint` | 只在该步进入时跑 320ms |
| G3 卡片入场 | 每张卡 1 个 `T0Enter` → `Opacity` + `Transform` | 卡片本体不重建 |
| G3/G8 进度环 | 1 个 `TweenAnimationBuilder` → 1 个 `CustomPaint` + 中心文字 | 环与数字共用同一个插值 |
| G4 tab 指示器 | 1 个 `AnimatedAlign` | 只有指示器这一块换位置 |
| G4 内容 cross-fade | 2 个 `FadeTransition`（旧 / 新各一） | 面板本体不重建 |
| G5 行让位 | 1 个 `TweenAnimationBuilder` → `Align(heightFactor)` + `ClipRect` | 只影响这一行的布局高度 |
| G6 状态点 | `missing`：1 个 `AnimatedBuilder` → 1 个 `Transform.scale`；`done`：1 个 `CustomPaint` | 不触碰所在行 |
| G7 高亮条 | 1 个 `AnimatedPositioned` | 量尺只在布局变化后跑一次，不是每帧 |
| G7 骨架 shimmer | 2 个 `AnimatedBuilder` → 2 个 `CustomPaint` | 骨架块本身不重建 |
| G9 按钮 / Toast | 1 个 `AnimatedScale` / 1 个 `AnimatedBuilder` | — |

**工作区三处（重点）——单帧内重建 widget 数：**

1. **左栏高亮条**：**1** 个（`AnimatedPositioned` 的隐式动画子树，即那个 `DecoratedBox`）。
   量尺 `_scheduleRailMeasure` 在每次 build 后 post-frame 跑一次，只有矩形真的变了才 `setState`，
   滑块移动期间不再回写。
2. **画布 cross-fade**：**4** 个 wrapper / 帧（两页各 `FadeTransition` + `SlideTransition`）；
   两页 720×405 的版面子树（封面页 + 内容页，各自约 40 个 widget）**0 次重建**，只是被重绘。
3. **前后对比弹层**：**2** 个 wrapper / 帧（路由的 `FadeTransition` + `ScaleTransition`）；
   弹层内两页共约 80 个 widget **0 次重建**。缩放会触发整块重绘（raster），这是 `scale` 的固有代价，
   弹层只在 220ms 内出现一次。

> **第二轮更新**：`--perf=` 已经能在 Web 上跑（`?perf=cold|theme|works|dialog|all`，与桌面
> `--perf=` 共用同一套场景代码），四场景的 p50/p95/max、掉帧计数与优化前后对比见
> [`帧耗时.md`](帧耗时.md)。下面这段是第二轮之前的记录，保留原样。

**`--perf=` 场景在这台机器上跑不了**：`--perf=A|B|C|D|E|soak` 走的是 `main(List<String> args)`
（`lib/main.dart:16` 起），只有桌面 runner 才会把 dart 参数传进来；这台 Linux 容器没有桌面
GTK 显示栈（`flutter run -d linux` 需要 GTK dev + 显示器），web 端 `main()` 也拿不到 dart 参数。
所以本轮**没有**帧耗时数字，上面给的是「每帧重建 widget 数」的结构估算 + 一条实测的重建次数断言，
不编帧率。

## 4. 三点判断，留给人拍板

1. **8px 状态点的「打勾描线」**：24px 的交付徽章里画的是真勾（`T0CheckBadge`，`CustomPainter` 描线）。
   但 `StatusDot` 在列表 / 胶囊里只有 6–8px，真勾在这里会糊成脏点，所以 done 的 300ms 描线落在
   **这个点自己的勾形笔画**上（同样 `CustomPainter` + `AnimationController`，不贴图、只播一次）。
   如果你要的就是「所有状态点里都画勾」，改 `status_dot.dart:121` 的 `strokeWidth` 上限即可，一行。
2. **G2「页面标题切换」**：现网里六个界面的标题都是各页常量，没有运行时换标题的入口，
   所以 `FlowHead` 的 `AnimatedSwitcher` 在本轮是「备用能力」——行为由 `test/motion_test.dart` 覆盖，
   页面上看不到它播。要真看到，得等某一页做「同名页换标题」。
3. **`T0Loops`（循环动效总开关）**：`AnimationController.repeat()` 会让 widget 测试的 `pumpAndSettle()`
   永远等不到静止（现有 18 个用例会在打开模块 / 工作区 / 交付页时超时）。所以新增
   `test/flutter_test_config.dart`，在测试入口把它关掉（等价于无动效环境），线上仍是真循环；
   `test/motion_test.dart` 里单独把开关打开验证了呼吸确实在跑。没有改任何一条既有断言。
4. **G7 的「左栏高亮条」只在桌面布局存在**：窄屏（<700px）工作区走的是顶部模块胶囊条
   （`_railStrip`），选中胶囊维持原来的即时高亮，没有滑动的面。要的话再给胶囊条补一条同参数滑块。
